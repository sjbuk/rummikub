# Game server

Authoritative Rummikub server: `server/` holds the tested core, `supabase/`
holds the deployment (Postgres migrations + Edge Functions). The web client
is unchanged and still plays P2P.

## Layout

- `server/` — framework-free TypeScript core + Vitest suites. Imports game
  rules from `src/game/` with explicit `.ts` extensions so the same files run
  under Node/Vitest and Deno. `fake-db.ts` is the in-memory `Db` for tests.
- `supabase/migrations/` — `rooms`, `seats`, `games` tables. RLS enabled
  with no permissive policies: only Edge Functions (service role) touch them.
- `supabase/functions/<name>/index.ts` — ten thin Deno wrappers (room
  CRUD + list + state, game start/commit/draw/draft, scheduled cleanup)
  around `server/handlers.ts`. Fully covered by `server/handlers.test.ts`.
- `supabase/functions/_shared/cors.ts`, `supabase-db.ts` — handwritten
  Deno-only helpers (preserved by sync).
- `supabase/functions/_shared/server/`, `_shared/src/` — GENERATED by
  `npm run server:sync-shared` (gitignored); byte-identical to the tested
  core, verified in CI with `diff`.

## One-time setup

1. Install the CLI: `npm i -g supabase` (or see
   [Supabase CLI docs](https://supabase.com/docs/guides/cli)).
2. `supabase link --project-ref "$SUPABASE_PROJECT_REF"`.
3. CI needs secrets: `SUPABASE_ACCESS_TOKEN`, `SUPABASE_PROJECT_REF`,
   `SUPABASE_DB_PASSWORD` (environment `supabase`).
4. Schedule `rooms-cleanup` (Supabase scheduled functions / pg_cron,
   e.g. hourly) — otherwise idle rooms accumulate.

## Commands

- `npm test` — full suite, including all server tests.
- `npm run server:sync-shared` — rebuild the generated function bundle.
- `npm run server:deploy` — sync + `supabase db push` + deploy all
  functions (requires a linked project).
- `supabase start` (`npm run server:dev`) — local stack for manual smoke
  tests; serve functions with `supabase functions serve`.

Deploys also run automatically on pushes to `master` that touch
`server/`, `supabase/`, `src/game/`, or the sync script, via
`.github/workflows/server-deploy.yml` (typecheck + tests + bundle-identity
check first, deploy after).
